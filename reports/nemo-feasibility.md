# NeMo Evaluator: local integration checked, standard benchmarks pending

Verified **2026-11-10**. The maintained observations, package hashes, run IDs and limitations are in [`results/nemo.json`](../results/nemo.json). This is a small framework-integration check, not an evaluation of general model quality.

## Actual outcome

NeMo Evaluator **0.3.0** listed 17 built-in benchmarks, then completed four project-authored prompts on the existing laptop model. All four returned HTTP 200, finished with `stop`, and passed NeMo's normalized `exact_match`; all also passed an independent strip-only comparison. There were no model errors or retries in the successful run. Run `20261110T205209Z_nemotron-3-nano-4b_ollama_laptop_nemo` took **27.78 seconds wall time**, including framework startup/shutdown, versus **24.23 seconds** reported by its evaluation loop.

The test used `nemotron-3-nano:4b-q4_K_M`, Homebrew Ollama 0.40.15, the existing reasoning-OFF proxy, one repeat per prompt, concurrency one, temperature zero, top_p one, seed 42 and `max_tokens:256`. It reused the original fixtures from [`harness/matched_replay.py`](../harness/matched_replay.py). No external dataset, model weights, Docker image, judge or hosted API was used. These are integration results; **GSM8K, MMLU and other standard benchmarks have not run**.

There was one preserved failure before success. The first adapter reused a dataset column named `expected`. NeMo 0.3.0 copied that column into metadata, then passed the expected answer both positionally and through `**metadata` to `verify`, causing a duplicate-argument error. The failed run `20261110T205027Z_nemotron-3-nano-4b_ollama_laptop_nemo` remains excluded. One correction mapped the original `expected` column to `answer`; prompts and reference answers stayed identical. No installed package source was patched. The mechanism is visible in the pinned [BYOB seed/verify implementation](https://github.com/NVIDIA-NeMo/Evaluator/blob/v0.3.0/src/nemo_evaluator/environments/custom.py) and [evaluation loop](https://github.com/NVIDIA-NeMo/Evaluator/blob/v0.3.0/src/nemo_evaluator/engine/eval_loop.py).

## Version and dependency decision

Fresh official metadata still lists [`nemo-evaluator` 0.3.0](https://pypi.org/pypi/nemo-evaluator/0.3.0/json), requiring Python 3.12–3.13. This package itself supplies `nel`. The separate [`nemo-evaluator-launcher` 0.2.6](https://pypi.org/pypi/nemo-evaluator-launcher/0.2.6/json) requires evaluator **below 0.3.0**, so it was not installed alongside the selected core. The current repository main version was 0.4.0 when captured; nightly documentation is not a version-pinned install contract. See the pinned [project metadata and entry point](https://github.com/NVIDIA-NeMo/Evaluator/blob/v0.3.0/pyproject.toml).

The original `.venv` remains unchanged: AIPerf 0.13.0 and python-dateutil 4.0.0 are still present, and NeMo is not installed there. A project-local, ignored `.scratch/nemo` overlay contains five explicitly pinned packages:

The overlay reuses already installed compatible dependencies. Its isolated dateutil pin satisfies botocore's `<3` constraint without changing the original environment. This incremental footprint describes this machine, not a clean installation. Package URLs and hashes are recorded in the maintained result.

## Reproduce the checked integration

In the prepared local overlay, first run discovery:

```bash
PYTHONPATH=.scratch/nemo .venv/bin/python -m nemo_evaluator.cli.main list --source builtin
```

The checked adapter is [`harness/nemo_fixture.py`](../harness/nemo_fixture.py), and all run settings are in [`configs/nemo-local-fixture.yaml`](../configs/nemo-local-fixture.yaml). With the existing Ollama model and reasoning proxy running:

```bash
HF_HUB_OFFLINE=1 HF_DATASETS_OFFLINE=1 PYTHONPATH=.scratch/nemo \
  .venv/bin/python -m nemo_evaluator.cli.main eval run \
  configs/nemo-local-fixture.yaml --output-dir runs/<new-run>/evaluation
```

The CLI starts and closes its own temporary adapter on loopback port 4000 to apply generation settings. The original Ollama and reasoning proxy services are preserved. No secret is needed; the config explicitly sets `api_key: null`. Logs and raw output stay under ignored `runs/`. The shell prefix only selects the isolated overlay for that command; it does not change system Python settings.

A fresh checkout will not contain the ignored overlay or original virtual environment. Provision a separate optional environment and verify its resolved dependency sizes before running; do not run an unpinned upgrade in the historical AIPerf environment. The recorded wheel list is the exact incremental setup used here, not a complete clean-machine dependency lock.

## What a standard benchmark still needs

GSM8K is a plausible next small deterministic-scoring subset. In the pinned 0.3.0 implementation, [its scorer uses an answer-line regular expression](https://github.com/NVIDIA-NeMo/Evaluator/blob/v0.3.0/src/nemo_evaluator/benchmarks/gsm8k.py), so this path does not require a paid judge or a Docker code sandbox. It does call Hugging Face `load_dataset` on `openai/gsm8k`, configuration `main`, split `test`. A `max_problems` limit becomes a split slice; it does **not** prove that download bytes are limited to that number of examples. Dataset version, license, download/cache footprint, frozen example IDs and output-budget adequacy must be checked before claiming a standard subset result. No such download occurred here. [Pinned dataset loader](https://github.com/NVIDIA-NeMo/Evaluator/blob/v0.3.0/src/nemo_evaluator/environments/custom.py).

The four-fixture run has no deliberately controlled warmup/cache treatment, and follows a failed run that warmed the model. Its timing is not comparable to the paired native replay. NeMo's `exact_match` normalizes case, Unicode, articles, punctuation and whitespace; it is not byte equality. Reasoning-token fields are unavailable/null in this output and must not be presented as measured zero. Human-label calibration remains separate and pending.

## GPU notebook preparation

[`harness/gpu_preflight.py`](../harness/gpu_preflight.py) is a read-only first-cell guard for the planned single-T4 notebook. It reuses the existing tested `runmeta` NVIDIA parsers, records GPU name/memory/driver/compute capability where available, and stops if the requested hardware or driver capability cannot be observed. It starts no model and downloads nothing.

```python
import subprocess, sys
subprocess.run([
    sys.executable, "-m", "harness.gpu_preflight",
    "--output", "runs/t4-preflight/gpu_preflight.json"
], check=True)
```

`nvidia-smi`'s CUDA version is the driver's supported maximum, not an installed CUDA toolkit. A successful guard would establish hardware visibility only. GPU access, quota, engine installation, compatible CUDA/engine pins, model weights and GPU measurements remain pending; this guard has not been run on a T4.
